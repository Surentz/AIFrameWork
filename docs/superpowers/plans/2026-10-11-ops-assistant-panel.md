# Ops Assistant (panel) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An administrator opens **Monitoring → Ask the assistant**, types a question, and watches
Claude's answer stream in — with a chip for each monitoring tool it consults — then asks follow-ups,
stops an answer, or starts a new conversation.

**Architecture:** A frontend-only feature over the backend PR 1 shipped (#116): a small SSE parser,
an `askAssistant` call that streams `POST /api/assistant/messages` through `fetch`, a pure reducer
plus a `useAssistantConversation` hook that owns the conversation, and an `AssistantPage` at
`/monitoring/assistant` with a tile on the Monitoring overview. The Playwright spec runs the real
API against the test-only `FakeMessagesApi`, so no test ever needs an Anthropic key.

**Tech Stack:** React 19, TypeScript 6 (strict, `exactOptionalPropertyTypes`,
`noUncheckedIndexedAccess`), TanStack Query, React Router, Vitest + Testing Library + MSW 3,
Playwright; one small change in `tests/PartnerSimulator` (C#).

**Spec:** `docs/superpowers/specs/2026-10-11-ops-assistant-design.md` §4 (frontend) and §5 (its
tests). PR 1's plan, `docs/superpowers/plans/2026-10-11-ops-assistant-backend.md`, and ADR 0033 are
background.

## Decided before planning

- **The event shape stays as PR 1 built it** (the review's deferred minor): each SSE `data:` is an
  `AssistantEventResponse` — `type` is `text` | `tool` | `done` | `error`; `text` carries `delta`,
  `tool` carries `tool` (not `name`), `done` carries `conversationId` and `outcome`, `error` nests a
  ProblemDetails under `problem`. It is already in `openapi/AiFramework.Api.json` and
  `frontend/src/api/schema.d.ts`, so the types below are aliases over the generated schema.
- **Comment lines** (`: keep-alive`, every 15 s) are the server's heartbeat and are ignored.
- **Pre-stream failures** (400, 404, 409, 429, 503) arrive as ordinary ProblemDetails responses and
  become `ApiError`s through `client.ts`, like every other request.

## Global Constraints

- `npm run lint` is `eslint . --max-warnings 0`: one warning fails. No `any`, no `!`, explicit return
  types on exported functions, components return `React.JSX.Element`.
- Models are aliases over `src/api/schema.d.ts` in `features/assistant/types.ts`; never restate a DTO.
- Server state belongs to TanStack Query (the status call); the streamed conversation is client state
  in a reducer — a stream is not a cacheable query. No `useEffect` for fetching.
- Every request goes through `src/api/client.ts`'s `send` (via `request`/`requestStream`).
- Tests: MSW with `onUnhandledFrame: 'error'`; never `vi.mock` the API client; query by role and
  accessible name; `findBy*`, never fixed timeouts; one behaviour per `it`.
- Copy: the note under the input reads exactly **"Answers are generated by Claude from monitoring
  data. Check before acting."**; the 429 message reads **"You've asked a lot in the last hour — try
  again later."**; the question limit is **2,000** characters.
- Commits: `feat(assistant): …`, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
  The PR is one `feat`.

## Review Focus

1. **A chunk boundary splits an event** — mid-line, mid-JSON, or between `\r` and `\n`. Expected:
   every event arrives once, intact. Tests in Task 1.
2. **The heartbeat reaches the page.** Expected: `: keep-alive` lines never render and never break
   parsing. Test in Task 1 (parser) and Task 4 (page, a keep-alive inside the stream).
3. **The admin navigates away mid-answer.** Expected: the request is aborted (nothing saved on the
   server, no state update after unmount). Test in Task 3.
4. **Stop, then ask again.** Expected: the stopped answer is marked stopped, the input re-enables,
   and the next question still carries the conversation's id (the server stored nothing for the
   stopped one, so the conversation continues from its last saved answer). Test in Task 4.
5. **A conversation the server no longer has** (24 h prune → `assistant.conversation_not_found`, or
   20 questions → `assistant.conversation_full`). Expected: a readable error, and **New
   conversation** recovers — the next request sends no conversation id. Test in Task 4.

- [ ] **Step 4: Write the parser**

`frontend/src/features/assistant/sse.ts`:

```ts
import type { AssistantEvent } from './types';

/**
 * Turns a text/event-stream body into the assistant's events. A network chunk can end anywhere —
 * mid-line, mid-JSON, between a CR and its LF — so whatever has not yet ended in a blank line is
 * kept for the next push. Comment lines (": keep-alive") are the server's heartbeat, not events.
 */
export class SseParser {
  private buffer = '';

  push(chunk: string): AssistantEvent[] {
    // A lone trailing CR may be half of a CRLF; it is normalised once its LF arrives.
    this.buffer = (this.buffer + chunk).replaceAll('\r\n', '\n');

    const events: AssistantEvent[] = [];
    for (let end = this.buffer.indexOf('\n\n'); end !== -1; end = this.buffer.indexOf('\n\n')) {
      const block = this.buffer.slice(0, end);
      this.buffer = this.buffer.slice(end + 2);

      const event = parseBlock(block);
      if (event !== undefined) {
        events.push(event);
      }
    }

    return events;
  }
}

function parseBlock(block: string): AssistantEvent | undefined {
  const data = block
    .split('\n')
    .filter((line) => line.startsWith('data:'))
    .map((line) => line.slice('data:'.length).trimStart())
    .join('\n');

  // A block of comments only (the keep-alive) carries no data.
  return data === '' ? undefined : (JSON.parse(data) as AssistantEvent);
}
```

```ts
import { HttpResponse } from 'msw';

const encoder = new TextEncoder();

/** One server-sent event, exactly as SseAssistantOutput writes it. */
export function sseEvent(event: { readonly type: string } & Record<string, unknown>): string {
  return `event: ${event.type}\ndata: ${JSON.stringify(event)}\n\n`;
}

/** A text/event-stream response that sends each chunk, then closes. */
export function sseResponse(...chunks: string[]): HttpResponse<ReadableStream> {
  return new HttpResponse(
    new ReadableStream({
      start(controller) {
        for (const chunk of chunks) {
          controller.enqueue(encoder.encode(chunk));
        }
        controller.close();
      },
    }),
    { headers: { 'Content-Type': 'text/event-stream' } },
  );
}

/** The same, but never closes: an answer still being written, for Stop and unmount tests. */
export function openSseResponse(...chunks: string[]): HttpResponse<ReadableStream> {
  return new HttpResponse(
    new ReadableStream({
      start(controller) {
        for (const chunk of chunks) {
          controller.enqueue(encoder.encode(chunk));
        }
      },
    }),
    { headers: { 'Content-Type': 'text/event-stream' } },
  );
}
```

```ts
/**
 * For the endpoints that answer a stream — the assistant's text/event-stream. Same error handling
 * as `request` for a failure before the stream starts; after that, failures arrive in the stream.
 */
export async function requestStream(
  path: string,
  init?: RequestInit,
): Promise<ReadableStream<Uint8Array>> {
  const response = await send(path, init);
  if (response.body === null) {
    throw new Error('The response has no body to stream.');
  }

  return response.body;
}
```

- [ ] **Step 5: Write the API module**

`frontend/src/api/assistant.ts`:

```ts
import { SseParser } from '../features/assistant/sse';
import type {
  AskAssistantRequest,
  AssistantEvent,
  AssistantStatus,
} from '../features/assistant/types';
import { request, requestStream } from './client';

export function getAssistantStatus(): Promise<AssistantStatus> {
  return request<AssistantStatus>('/api/assistant');
}

export interface AskOptions {
  readonly signal: AbortSignal;
  readonly onEvent: (event: AssistantEvent) => void;
}

/**
 * Asks one question and hands each event to `onEvent` as it arrives. Resolves after `done` or
 * `error`. Rejects with an ApiError for a failure before the stream started (400, 404, 409, 429,
 * 503), with the abort when `signal` fires, and with an Error if the stream ends without either.
 */
export async function askAssistant(body: AskAssistantRequest, options: AskOptions): Promise<void> {
  const stream = await requestStream('/api/assistant/messages', {
    method: 'POST',
    body: JSON.stringify(body),
    signal: options.signal,
  });

  const reader = stream.getReader();
  const decoder = new TextDecoder();
  const parser = new SseParser();
  let finished = false;

  for (let read = await reader.read(); !read.done; read = await reader.read()) {
    for (const event of parser.push(decoder.decode(read.value, { stream: true }))) {
      options.onEvent(event);
      finished ||= event.type === 'done' || event.type === 'error';
    }
  }

  if (!finished) {
    throw new Error('The answer stopped before it finished. Try again.');
  }
}
```

`frontend/src/features/assistant/conversation.ts`:

```ts
import { ApiError } from '../../api/client';
import type { AssistantEvent, AssistantOutcome } from './types';

export interface AssistantMessage {
  readonly id: number;
  readonly role: 'user' | 'assistant';
  readonly text: string;
  readonly tools: readonly string[];
  readonly outcome?: AssistantOutcome | undefined;
  readonly stopped?: boolean | undefined;
}

export interface ConversationState {
  readonly conversationId: string | undefined;
  readonly messages: readonly AssistantMessage[];
  readonly streaming: boolean;
  readonly error: Error | undefined;
}

export type ConversationAction =
  | { readonly type: 'asked'; readonly question: string }
  | { readonly type: 'event'; readonly event: AssistantEvent }
  | { readonly type: 'failed'; readonly error: Error }
  | { readonly type: 'stopped' }
  | { readonly type: 'reset' };

export const initialConversation: ConversationState = {
  conversationId: undefined,
  messages: [],
  streaming: false,
  error: undefined,
};

/**
 * The conversation as the page shows it. Pure, so every transition is a plain unit test. The
 * conversation id is the server's (from `done`); a stopped or failed question saved nothing there,
 * so the id is kept and the next question continues from the last saved answer.
 */
export function conversationReducer(
  state: ConversationState,
  action: ConversationAction,
): ConversationState {
  switch (action.type) {
    case 'asked':
      return {
        ...state,
        streaming: true,
        error: undefined,
        messages: [
          ...state.messages,
          { id: state.messages.length, role: 'user', text: action.question, tools: [] },
          { id: state.messages.length + 1, role: 'assistant', text: '', tools: [] },
        ],
      };
    case 'event':
      return applyEvent(state, action.event);
    case 'failed':
      return { ...dropEmptyAnswer(state), streaming: false, error: action.error };
    case 'stopped':
      return state.messages.length === 0
        ? state
        : { ...updateAnswer(state, (m) => ({ ...m, stopped: true })), streaming: false };
    case 'reset':
      return initialConversation;
  }
}

function applyEvent(state: ConversationState, event: AssistantEvent): ConversationState {
  switch (event.type) {
    case 'text':
      return updateAnswer(state, (m) => ({ ...m, text: m.text + (event.delta ?? '') }));
    case 'tool':
      return updateAnswer(state, (m) => ({ ...m, tools: [...m.tools, event.tool ?? 'a tool'] }));
    case 'done':
      return {
        ...updateAnswer(state, (m) => ({ ...m, outcome: event.outcome ?? undefined })),
        conversationId: event.conversationId ?? state.conversationId,
        streaming: false,
      };
    case 'error':
      return { ...dropEmptyAnswer(state), streaming: false, error: toApiError(event.problem) };
    default:
      return state;
  }
}

function updateAnswer(
  state: ConversationState,
  change: (message: AssistantMessage) => AssistantMessage,
): ConversationState {
  const last = state.messages.at(-1);
  if (last?.role !== 'assistant') {
    return state;
  }

  return { ...state, messages: [...state.messages.slice(0, -1), change(last)] };
}

/** An answer with no text and no tools says nothing; the error shown in its place does. */
function dropEmptyAnswer(state: ConversationState): ConversationState {
  const last = state.messages.at(-1);
  return last?.role === 'assistant' && last.text === '' && last.tools.length === 0
    ? { ...state, messages: state.messages.slice(0, -1) }
    : state;
}

function toApiError(problem: AssistantEvent['problem']): ApiError {
  // traceId is a ProblemDetails extension, so the generated type does not name it.
  const extensions = (problem ?? {}) as Readonly<Record<string, unknown>>;
  const traceId = typeof extensions['traceId'] === 'string' ? extensions['traceId'] : undefined;

  return new ApiError(Number(problem?.status ?? 500), {
    ...(problem?.title ? { title: problem.title } : {}),
    ...(problem?.detail ? { detail: problem.detail } : {}),
    ...(traceId ? { traceId } : {}),
  });
}
```

```ts
import { useCallback, useEffect, useReducer, useRef } from 'react';
import { askAssistant } from '../../api/assistant';
import { conversationReducer, initialConversation } from './conversation';
import type { ConversationState } from './conversation';

export interface AssistantConversation extends ConversationState {
  readonly ask: (question: string) => void;
  readonly stop: () => void;
  readonly startOver: () => void;
}

/**
 * One conversation with the assistant. A stream is not a cacheable query, so this is client state
 * in a reducer rather than TanStack Query. An answer in flight is aborted on Stop, on New
 * conversation, and when the page unmounts — the server then saves nothing for that question.
 */
export function useAssistantConversation(): AssistantConversation {
  const [state, dispatch] = useReducer(conversationReducer, initialConversation);
  const inFlight = useRef<AbortController | null>(null);

  const ask = useCallback(
    (question: string) => {
      const controller = new AbortController();
      inFlight.current = controller;
      dispatch({ type: 'asked', question });

      void askAssistant(
        { conversationId: state.conversationId ?? null, question },
        { signal: controller.signal, onEvent: (event) => dispatch({ type: 'event', event }) },
      ).catch((error: unknown) => {
        if (controller.signal.aborted) {
          dispatch({ type: 'stopped' });
          return;
        }

        dispatch({ type: 'failed', error: error instanceof Error ? error : new Error(String(error)) });
      });
    },
    [state.conversationId],
  );

  const stop = useCallback(() => {
    inFlight.current?.abort();
  }, []);

  const startOver = useCallback(() => {
    inFlight.current?.abort();
    dispatch({ type: 'reset' });
  }, []);

  // Not a fetch: the cleanup that aborts an answer still streaming when the page goes away.
  useEffect(
    () => () => {
      inFlight.current?.abort();
    },
    [],
  );

  return { ...state, ask, stop, startOver };
}
```

```tsx
function AssistantChat(): React.JSX.Element {
  const conversation = useAssistantConversation();
  const [question, setQuestion] = useState('');
  const trimmed = question.trim();

  function submit(event: FormEvent<HTMLFormElement>): void {
    event.preventDefault();
    if (trimmed === '' || conversation.streaming) {
      return;
    }

    conversation.ask(trimmed);
    setQuestion('');

    <section className="assistant">
      <h1>Ask the assistant</h1>

      </ol>

      {conversation.error && <AssistantError error={conversation.error} />}

      <form className="assistant-form" onSubmit={submit}>
        <label htmlFor="assistant-question">Your question</label>
        <textarea
          id="assistant-question"
          value={question}
          maxLength={MaxQuestionLength}
          rows={3}
          disabled={conversation.streaming}
          onChange={(event) => {
            setQuestion(event.target.value);
          }}
        />
        <p className="muted">
```
